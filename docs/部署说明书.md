# 零废弃知识库 · 部署说明书

这份说明书给安徽省六尺巷慈善基金会里负责把网站放到网上的同事。不需要会写代码。每一步都是：在腾讯云网页上点哪里，或者把框里的字整段粘贴进一个文字窗口。

做完以后，别人用一个网址打开知识库：先看介绍，登录后可以翻资料书架、打开原文、向这些资料提问。管理员可以在网页里上传新资料、上下架、看谁在用。

网站程序已经写好，放在一台已经能打开的电脑上。这份说明书要做的事，是买好腾讯云上的域名和服务器，把这台电脑里的程序和资料搬上去，并让它以后还能继续用。

## 先做哪个

按这个顺序。前面两步可以同一天做完，备案要等。

| 顺序 | 做什么 | 在哪里做 | 要多久 |
| --- | --- | --- | --- |
| 1 | 用基金会身份注册并实名 | 腾讯云网站 | 当天，证件审核可能 1 到 3 个工作日 |
| 2 | 确定网址，并完成域名实名 | 腾讯云「域名注册」 | 实名一般 1 到 3 个工作日 |
| 3 | 买一台轻量应用服务器 | 腾讯云「轻量应用服务器」 | 付款后几分钟就能登录 |
| 4 | 办备案 | 腾讯云「ICP 备案」 | 腾讯云初审 1 到 2 个工作日，安徽省通信管理局最长 20 个工作日 |
| 5 | 把程序和资料搬上服务器，自己先打开看 | 自己的电脑 + 服务器网页终端 | 半天。第一次安装要等十几分钟 |
| 6 | 等备案通过，把域名指到服务器，打开加密访问 | 路 A 在阿里云解析里加记录；证书在腾讯云申请 | 通过当天可以做完 |
| 7 | 自己走一遍读者和管理员会做的事 | 浏览器 | 半小时 |
| 8 | 网站开通后 30 天内做公安备案 | 全国互联网安全管理服务平台 | 按页面提交 |

备案通过之前，用域名打不开正式网站。第 5 步不用等备案，用服务器的数字地址自己检查。

## 开始前放在手边的东西

- 基金会法人登记证书，上面有统一社会信用代码。名称是「安徽省六尺巷慈善基金会」。
- 法定代表人身份证。
- 网站负责人的身份证和手机。这个手机以后要收备案短信，换号要重新办手续。负责人可以是法定代表人，也可以是被授权的工作人员。安徽省如果要求必须是法定代表人，以备案页面当页的说明为准，页面多要的材料按页面补。
- 基金会公章。备案核验单要盖章。
- 一张能付给腾讯云的卡或对公账户。
- 已经能打开知识库的那台电脑。程序、资料和钥匙都在这台电脑上。
- 阿里云百炼的账号。读者每提问一次，费用出在阿里云，不出在腾讯云。
- SoMark 的钥匙。只有管理员上传新资料、需要把原文转成可检索文字时才用。没有这把钥匙，上传的文件可以留在书架上，但提问用不到它的正文。

三个名字必须一字不差，都是「安徽省六尺巷慈善基金会」：腾讯云实名、域名持有者、备案主体。用个人姓名实名的账号，不能直接给基金会备案。

钥匙只放在两处：那台电脑上的 `backend/.env`，以及服务器上同名的那个文件。不要发到微信、邮件或这份说明书里。

## 1. 注册腾讯云，并用基金会实名

1. 打开 [腾讯云](https://cloud.tencent.com/)，注册一个新账号。手机和邮箱留给基金会，不要用经办人私人邮箱当唯一联系方式。
2. 登录后进入「账号中心 → 实名认证」，选择单位认证，单位名称填写「安徽省六尺巷慈善基金会」，证件用基金会法人登记证书。
3. 按页面上传证件、完成法定代表人或授权人的人脸核验。
4. 认证通过之前，先不要买域名。买了也可以，但持有者信息容易填错，后面备案会被退回。

## 2. 决定网址

网站页脚现在写着「皖ICP备2025104469号-1」。这是基金会已经备案过的那个网站的号码，对应官网域名 `lcx-foundation.org.cn`。这个域名的解析现在在阿里云万网，域名服务器是 `dns25.hichina.com` 和 `dns26.hichina.com`。`www` 已经指向现在的官网。知识库有两条路。

### 路 A：用官网下面的一个名字

例如 `kb.lcx-foundation.org.cn`。不用再买域名，也不用把域名搬到腾讯云。页脚可以继续用现在这个备案号。

在阿里云的解析里只新增一条记录，主机记录填 `kb`。已经存在的记录，尤其是 `www`，保持不动。把域名的服务器改成腾讯云，官网会一起断线。

还是要在腾讯云办一次「接入备案」：官网原来接在哪家服务商，就还留在哪家；知识库这台新服务器在腾讯云，等于给同一个域名增加腾讯云这家接入商。

### 路 B：单独买一个新域名

知识库有自己的网址。在已有主体下面「新增网站」，通过后会拿到一个新号码，通常是「皖ICP备2025104469号-2」。上线前要把页脚那一行改成新号码，并链到 [工信部备案管理系统](https://beian.miit.gov.cn/)。这一行在网站程序的页脚里，改的时候把新号码交给维护网站的人，让对方换上再重新发布。

新域名建议用 `.cn`。国内机构备案时材料最直接。

购买步骤：

1. 登录腾讯云，顶部搜索「域名注册」。
2. 输入想要的名字，看它是否可以注册。选中 `.cn`，加入购物车并付款。一次买一年或更久。
3. 持有者信息选择基金会，不要选经办人个人。
4. 付款后进入「域名控制台 → 实名认证」，上传基金会证件。`.cn` 域名实名通过之前，不能解析，也不能备案。
5. 实名通过后，在同一页下载「域名证书」，备案要上传。

下面用 `kb.lcx-foundation.org.cn` 作为例子。走新域名时，把后文所有这个名字换成你买到的域名。

## 3. 买服务器

买「轻量应用服务器」，不要买页面更大的「云服务器」。对这个网站，轻量的控制台够用，步骤也少。

打开腾讯云，搜索「轻量应用服务器」，新建：

| 选项 | 选什么 |
| --- | --- |
| 地域 | 上海。南京、广州也可以。三个都在中国境内，都能备案。选好后不要再换地域，备案和这台机器绑在一起 |
| 可用区 | 页面默认的即可 |
| 镜像 | 「系统镜像」里的 Ubuntu 22.04。不要选 WordPress、宝塔或「应用镜像」 |
| 套餐 | 4 核、8 GB 内存、系统盘 80 GB 或更大。回答问题要用这台机器自己查阅原文，内存小于 8 GB 时，安装或同时有几个人提问会中途停住。原文以后还会增加，磁盘留出余量 |
| 流量 | 选每月 1000 GB 或更高。平时翻页很省，有人下载整本资料才用得多。如果套餐写的是带宽而不是流量，选 6 Mbps 或更高 |
| 时长 | 一年。备案要求这台机器按月购买至少 3 个月，并且在备案期间还剩至少 1 个月。买一年两项都满足，也比按月续更省事 |
| 登录 | 设置一长串密码，写进基金会的密码本。登录名先记住，Ubuntu 一般是 `ubuntu` |
| 数量 | 1 台 |

付款后，在实例列表里能看到一行。记下两样东西：

- 公网 IP：一串数字，例如 `1.2.3.4`。后面域名要指到它。
- 实例名称和到期日。到期日写进日历，提前一个月续费。到期后网站会关，资料还在，续上费再开。

然后设置防火墙。进入这台实例，左侧找「防火墙」：

| 端口 | 是否放行 | 原因 |
| --- | --- | --- |
| 22 | 放行 | 从自己的电脑把资料传上去时要用。来源能填办公室网络就填办公室；不知道就先选全部，传完再改 |
| 80 | 放行 | 读者用网址打开网站 |
| 443 | 放行 | 加密访问 |
| 8080 | 备案通过前临时放行 | 自己用数字地址检查。检查完、域名已经能打开之后，删掉这一条 |
| 4000 | 不要放行 | 这是网站内部接口。读者不需要直接碰到它 |

备案通过前，有人用域名访问 80 或 443，会看到腾讯云的未备案提示。这是正常的，不是程序坏了。

## 4. 备案

主体已经有「皖ICP备2025104469号」。这次不是从零开始办一个新主体。

- 路 A（子域名）：办「接入备案」。域名填 `lcx-foundation.org.cn`。
- 路 B（新域名）：办「新增网站」。域名填新买的那一个。网站名称写「六尺巷零废弃知识库」。

打开腾讯云，搜索「ICP 备案」，按页面选择备案类型。也可以用微信里的腾讯云备案小程序，材料是同一套。

填写时注意：

- 省份选安徽。管局是安徽省通信管理局，和服务器买在上海不冲突。
- 单位性质选「基金会」。
- 云资源选刚才那台轻量应用服务器。
- 网站服务内容不要勾新闻、出版、药品、广播电影电视、网络游戏。那些要额外资质。这个站是公益机构的资料查阅，服务类型选「其他」，备注写：提供零废弃相关公开资料的查阅和基于这些资料的提问。
- 网站负责人填写第 1 节准备的那个人。手机号必须是本人能收到短信的号码。
- 核验单从页面下载，打印、盖公章、拍照上传。拍照要看到公章和四个角。

提交后的等待：

1. 腾讯云初审，1 到 2 个工作日。退回时看短信里的原因，改完重新提交。常见原因是证件边缘被切掉、名字有一个字不一致、网站名称过于空泛。
2. 初审通过后，工信部向网站负责人手机发验证码。24 小时内打开 [工信部备案管理系统](https://beian.miit.gov.cn/)，按短信完成核验。超时要重新来过。
3. 安徽省通信管理局审核，最长 20 个工作日。通过后腾讯云发短信和邮件。
4. 网站负责人可能要做一次视频核验：腾讯云备案小程序里，光线明亮，身份证在手边。

备案号下来之前，继续做第 5 步。第 6 步等短信。

## 5. 把本机的内容搬上服务器

这一节分两段。第一段在已经能打开知识库的那台苹果电脑上做。第二段在腾讯云网页里的终端上做。

终端是一个黑底白字的窗口。你不需要理解里面的句子。一次粘贴一整段，然后按回车，等它停下来，再粘贴下一段。中途出现红色的 `Error` 或 `失败`，停下来，把那一段最后 20 行复制给维护网站的人。窗口一直在往下滚、没有红色报错，是在正常安装。

### 5.1 在自己的电脑上打四个包

打开「启动台 → 其他 → 终端」。苹果电脑也可以按 `Command + 空格`，输入「终端」，回车。

把下面整段粘贴进去，回车。它会在桌面生成一个文件夹「上传到服务器」，里面有四个压缩包。原文大约 3.5 GB，这一步要等几分钟。

```bash
cd "/Users/evawang/Desktop/六尺巷"
mkdir -p "$HOME/Desktop/上传到服务器"
tar -czf "$HOME/Desktop/上传到服务器/1-网站程序.tgz" \
  --exclude node_modules \
  --exclude '*/node_modules' \
  --exclude backend/data \
  --exclude backend/.env \
  --exclude inputs \
  --exclude .git \
  --exclude .DS_Store \
  .
tar -czf "$HOME/Desktop/上传到服务器/2-语料.tgz" \
  -C "/Users/evawang/Desktop/六尺巷/backend/data" corpus
tar -czf "$HOME/Desktop/上传到服务器/3-账号和书架.tgz" \
  -C "/Users/evawang/Desktop/六尺巷/backend/data" app.db ask-vectors
tar -czf "$HOME/Desktop/上传到服务器/4-原文PDF.tgz" \
  -C "/Users/evawang/Desktop/六尺巷/inputs/六尺巷基金会 零废弃知识库附件包 260929" .
```

四个包分别是：

| 文件 | 是什么 |
| --- | --- |
| 1-网站程序.tgz | 网站本身，含查阅原文用的模型。大约几十 MB |
| 2-语料.tgz | 已经整理成可检索文字的资料 |
| 3-账号和书架.tgz | 现有注册账号、书架索引、已经算好的检索数据 |
| 4-原文PDF.tgz | 读者要打开和下载的原文。文件名不要改，网站靠文件名找到原文 |

桌面上能看到这四个文件，这一步就完成了。钥匙文件 `backend/.env` 故意没有打进包里。

如果原文后来又放进了别的文件夹，先把那些 PDF 放进 `4-原文PDF.tgz` 所在的那次打包里。同名文件只保留先找到的一份。

### 5.2 传到服务器

1. 腾讯云轻量应用服务器列表里，点这台机器的「登录」。用购买时设的密码进入网页终端。
2. 确认防火墙已经放行 22。
3. 回到自己电脑的终端，把下面这一段里的 `1.2.3.4` 换成公网 IP，整段粘贴。它会问你密码，输入购买时设的那一串。输入时屏幕不显示字符，这是正常的，输入完按回车。

```bash
scp -r "$HOME/Desktop/上传到服务器" ubuntu@1.2.3.4:/home/ubuntu/
```

如果提示 `ubuntu` 不存在，说明登录名不是 ubuntu。在网页终端里输入 `whoami` 后回车，把上面命令里的 `ubuntu` 换成屏幕显示的那个词，`/home/ubuntu/` 也换成 `/home/那个词/`。

传完后，网页终端里输入：

```bash
ls /home/ubuntu/上传到服务器
```

能看到那四个 `.tgz` 文件就可以继续。

### 5.3 放到固定位置

在网页终端里整段粘贴：

```bash
sudo -i
mkdir -p /root/zero-waste-portal /root/shelf-corpus /root/pdfs /root/zero-waste-portal/backend/data
tar -xzf "/home/ubuntu/上传到服务器/1-网站程序.tgz" -C /root/zero-waste-portal
tar -xzf "/home/ubuntu/上传到服务器/2-语料.tgz" -C /root/shelf-corpus --strip-components=1
tar -xzf "/home/ubuntu/上传到服务器/3-账号和书架.tgz" -C /root/zero-waste-portal/backend/data
tar -xzf "/home/ubuntu/上传到服务器/4-原文PDF.tgz" -C /root/pdfs
ls /root/shelf-corpus/data/app.db
ls /root/shelf-corpus/storage/markdown
ls /root/zero-waste-portal/backend/data/app.db
ls /root/zero-waste-portal/backend/models/Xenova/bge-small-zh-v1.5/onnx/model_quantized.onnx
find /root/pdfs -name '*.pdf' | head
```

每一行 `ls` 都应该打出一条路径，而不是 `No such file`。`find` 应该打出若干 PDF 文件名。语料的两个路径是 `data/app.db` 和 `storage/markdown`。模型文件缺失的话，后面的安装会直接停住，回到 5.1 重新打包，确认电脑上的 `backend/models` 还在。

提示符现在是 `root@...#`。后面的命令都在这个状态下粘贴。

### 5.4 写钥匙文件

先生成网站自己的登录钥匙。粘贴：

```bash
openssl rand -hex 32
```

屏幕打出一长串字母和数字。用鼠标选中它，复制。这串字就是后面的 `JWT_SECRET`。换掉它之后，所有人要重新登录，账号还在。

然后打开写字板：

```bash
nano /root/zero-waste-portal/backend/.env
```

把下面这段粘贴进去。三处要改：

- `JWT_SECRET` 后面换成刚才那一串。
- `BAILIAN` 开头的三行，从自己电脑上的 `backend/.env` 原样抄过来。那台电脑上用文本编辑打开这个文件即可，不要把它发到聊天窗口。接口地址通常是 `https://dashscope.aliyuncs.com/compatible-mode/v1`，模型名以那台电脑上已经写好的为准。
- 有 SoMark 钥匙时，把 `SOMARK_API_KEY` 换成真的。多把钥匙用英文分号隔开。还没有就先留着 `replace-me`，上传转换之前再补。

```text
NODE_ENV=production
PORT=4000
JWT_SECRET=这里换成刚才生成的一长串
DB_URL=file:../data/app.db
BAILIAN_API_KEY=从本机.env抄过来
BAILIAN_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
BAILIAN_MODEL=从本机.env抄过来
SOMARK_API_KEY=replace-me
```

保存：按 `Ctrl + O`，回车，再按 `Ctrl + X`。

检查没有把「这里换成」这几个字留在文件里：

```bash
grep -E 'JWT_SECRET|BAILIAN_MODEL' /root/zero-waste-portal/backend/.env
```

应当看到钥匙那一串和模型名，不应当看到「这里换成」或空的等号。

### 5.5 安装并启动

先安装 Docker。这是用来把网站装进一个固定环境里的工具，装一次即可。整段粘贴，等它自己停：

```bash
apt-get update
apt-get install -y ca-certificates curl
install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://mirrors.cloud.tencent.com/docker-ce/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
chmod a+r /etc/apt/keyrings/docker.asc
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] https://mirrors.cloud.tencent.com/docker-ce/linux/ubuntu $(. /etc/os-release && echo "$VERSION_CODENAME") stable" > /etc/apt/sources.list.d/docker.list
apt-get update
apt-get install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin
systemctl enable --now docker
mkdir -p /etc/docker
cat > /etc/docker/daemon.json << 'EOF'
{
  "registry-mirrors": ["https://mirror.ccs.tencentyun.com"]
}
EOF
systemctl restart docker
docker compose version
```

最后一行应当打出 `Docker Compose version v2...`。打不出来就停，把屏幕最后 20 行发给维护网站的人。

再启动网站。第一次会下载运行环境并编译，常常要 10 到 20 分钟。不要关网页终端。

```bash
cd /root/zero-waste-portal
docker compose -f deploy/docker-compose.yml up -d --build
```

停下来之后执行：

```bash
docker compose -f deploy/docker-compose.yml ps
curl -s http://127.0.0.1:4000/health
```

两行容器的状态都是 `running` 或 `healthy`，并且健康检查打出 `{"ok":true}`，网站程序就已经在跑。

然后把语料接上书架。这一步不覆盖已经注册的账号：

```bash
docker compose -f deploy/docker-compose.yml exec backend node backend/dist/modules/docs/docs.corpus.sync.cli.js
```

它会打出一段 JSON。里面有同步的条数，没有 `失败` 两个字，就可以。

```

把 `1.2.3.4` 换成公网 IP。应当看到知识库介绍。备案没通过时这个地址可以看，域名还不行。

如果打不开：回到网页终端执行下面这行，把最后 30 行复制下来。

```

同时确认防火墙里 8080 仍是放行的。

## 6. 域名指到服务器，并打开加密

等备案通过的短信到了再做。通过之前做了，读者打开域名会看到未备案页面。

### 6.1 解析

路 A 在阿里云加，路 B 在腾讯云加。两条路都只加记录，不改域名的服务器。

路 A：

1. 用当初注册 `lcx-foundation.org.cn` 的阿里云账号登录 [阿里云](https://www.aliyun.com/)。腾讯云账号里看不到这个域名。不知道密码时，问现在负责基金会官网的人。
2. 控制台顶部搜索「云解析 DNS」，进入权威域名列表。
3. 找到 `lcx-foundation.org.cn`，点「解析设置」。
4. 点「添加记录」，只填这一条：

| 项目 | 填写 |
| --- | --- |
| 记录类型 | A |
| 主机记录 | `kb` |
| 解析请求来源 | 默认 |
| 记录值 | 腾讯云这台轻量服务器的公网 IP |
| TTL | 10 分钟 |

5. 保存。列表里原有的记录不要点修改或删除，尤其是主机记录为 `www` 的那一条，那是现在的官网。

这样读者打开 `kb.lcx-foundation.org.cn` 会到知识库，打开 `www.lcx-foundation.org.cn` 仍是官网。

路 B：腾讯云搜索「云解析 DNS」，进入新买的域名，添加两条 A 记录。主机记录分别填 `@` 和 `www`，记录值都填公网 IP。

十分钟后再做下一步。想确认时，在自己电脑的终端粘贴（域名按实际替换）：

```bash
ping -c 1 kb.lcx-foundation.org.cn
```

打出的 IP 和服务器公网 IP 一致即可。`ping` 本身超时没有关系，很多服务器不回应 ping，只要括号或结果里的 IP 是对的。

### 6.2 免费证书

1. 腾讯云搜索「SSL 证书」，申请免费证书。
2. 域名填实际要用的那个，例如 `kb.lcx-foundation.org.cn`。路 B 如果希望带 `www` 和不带 `www` 都能开，按页面申请一张包含这两个名字的证书；页面不允许就申请两张。
3. 验证方式选手动 DNS。路 A 的解析在阿里云，腾讯云不能自动写记录。页面会给出一条主机记录（多半是 `_dnsauth.kb`）和一串记录值。回到阿里云这个域名的解析设置，添加一条 TXT 记录，主机记录和记录值按证书页面原样填写。状态变成「已签发」再往下。路 B 的域名如果就在这个腾讯云账号里，可以选自动 DNS。
4. 状态变成「已签发」后，下载证书，格式选 Nginx。得到一个压缩包。
5. 用 5.2 的同样办法，把这个压缩包传到服务器的 `/home/ubuntu/`。不要把证书压缩包发到微信。

在网页终端先解出来。压缩包的文件名以你下载的为准，下面用 `证书.zip` 指代它：

```bash
sudo -i
apt-get install -y nginx unzip
mkdir -p /etc/nginx/ssl /root/cert
unzip "/home/ubuntu/证书.zip" -d /root/cert
find /root/cert -type f
```

`find` 会列出一个 `.crt`（或文件名里带 bundle 的证书）和一个 `.key`。把下面两行里的路径换成 `find` 打出来的那两条，再粘贴：

```bash
cp /root/cert/这里换成.crt的路径 /etc/nginx/ssl/site.crt
cp /root/cert/这里换成.key的路径 /etc/nginx/ssl/site.key
chmod 600 /etc/nginx/ssl/site.key
```

系统自带的 Nginx 只负责加密和转发，网站程序仍在 8080，两份互不干扰。

写入转发规则。把 `kb.lcx-foundation.org.cn` 换成真实域名后整段粘贴：

```bash
cat > /etc/nginx/sites-available/zero-waste << 'EOF'
server {
    listen 80;
    server_name kb.lcx-foundation.org.cn;
    return 301 https://$host$request_uri;
}
server {
    listen 443 ssl;
    server_name kb.lcx-foundation.org.cn;
    ssl_certificate     /etc/nginx/ssl/site.crt;
    ssl_certificate_key /etc/nginx/ssl/site.key;
    client_max_body_size 50m;
    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header Connection "";
        proxy_buffering off;
        proxy_read_timeout 300s;
    }
}
EOF
ln -sf /etc/nginx/sites-available/zero-waste /etc/nginx/sites-enabled/zero-waste
rm -f /etc/nginx/sites-enabled/default
nginx -t
systemctl reload nginx
```

`nginx -t` 打出 `syntax is ok` 和 `test is successful` 之后，reload 才生效。打出 `failed` 就不要 reload，把那几行发给维护网站的人。

浏览器打开 `https://kb.lcx-foundation.org.cn`。地址栏有锁，页面是知识库介绍。然后回到防火墙，删掉 8080 那一条。以后读者只用域名。

免费证书有到期日，在 SSL 证书页面能看到。提前两周按同样步骤重新申请，把新的 `.crt` 和 `.key` 覆盖到 `/etc/nginx/ssl/`，再执行：

```bash
nginx -t && systemctl reload nginx
```

到期不续的话，读者会看到浏览器的安全警告，网站数据还在。

## 7. 上线当天点一遍

用一个没有管理员权限的手机号，换一台没开过这个站的电脑：

1. 打开域名。未登录时先看到介绍。
2. 不登录，打开资料书架，能按主题翻到书。
3. 点开一本资料。应当转到登录。注册并登录后，能预览、能下载。
4. 进入 AI 助手，问一个库里有的问题，例如某份已经上架的资料里写过的规定。回答应当在一两分钟内出现，句子上的编号能点开到来源。
5. 问一个库里没有的问题。回答应当说明库里没有依据。
6. 退出登录。

再用管理员账号：

1. 打开「管理」。能看到数据看板、资料管理、注册信息、问题反馈、系统设置。
2. 资料管理里把一本资料下架。退出后用普通账号确认书架上没有它，提问也不再引用它。再上架回来。
3. 系统设置里确认「百炼密钥」显示已配置。要更换时，把新钥匙贴进密码框并保存。留空表示不改。模型名和接口地址也可以在这一页改，保存后立刻生效，不用重启。
4. 用户权限里，可以给某个已注册用户打开或关掉预览、下载、管理。不能取消自己的管理权限。

上面这些都通过，就可以把域名发给读者。

## 8. 公安备案

网站用域名对外打开之后 30 天内，用基金会身份登录 [全国互联网安全管理服务平台](https://beian.mps.gov.cn/)，按页面提交公安备案。材料和 ICP 备案相近：基金会证件、负责人身份证、域名、服务器 IP。办下来的编号按页面要求放进页脚。这一项和腾讯云的 ICP 备案是两件手续。

## 9. 以后怎么维护

### 在网页里就能做的

用管理员登录：

| 要做的事 | 去哪里 |
| --- | --- |
| 看有多少人来过、问过什么 | 管理 → 数据看板 |
| 上传一份新的 PDF、Word 或 Excel | 管理 → 资料管理。单个文件不超过 50 MB |
| 暂时不公开某份资料 | 资料管理里下架。文件还在，可以再上架 |
| 看读者提交的问题 | 管理 → 问题反馈 |
| 更换百炼的模型、接口地址或钥匙 | 管理 → 系统设置 |
| 让某位同事成为管理员，或收回预览和下载 | 系统设置里的用户权限 |

上传之后，页面会登记一次文档转换。配了 SoMark 钥匙时，转换完成后这份资料进入书架和提问。超过 30 MB 的文件会在后台转，稍等再刷新。转换失败时，原文仍留在书架，提问用不到正文。没有钥匙时，只登记，不转换。

### 要进服务器一次的

更换 SoMark 钥匙：

```bash
sudo -i
nano /root/zero-waste-portal/backend/.env
```

改 `SOMARK_API_KEY` 那一行，保存退出，然后：

```bash
cd /root/zero-waste-portal
docker compose -f deploy/docker-compose.yml up -d --force-recreate backend
```

看程序是否还在：

```bash
curl -s http://127.0.0.1:4000/health
docker compose -f /root/zero-waste-portal/deploy/docker-compose.yml logs --tail 50 backend
```

健康检查仍是 `{"ok":true}`。

新增一批原文 PDF：用 5.2 的方式传到服务器，放进 `/root/pdfs`，文件名与入库时一致。然后重新接一次书架：

```bash
cd /root/zero-waste-portal
docker compose -f deploy/docker-compose.yml exec backend node backend/dist/modules/docs/docs.corpus.sync.cli.js
```

### 程序更新

维护网站的人给出新版本之后：

1. 先做快照，见下一节。
2. 只替换 `/root/zero-waste-portal` 里的程序文件。不要覆盖这三处：`backend/.env`、`backend/data`、`/root/shelf-corpus`、`/root/pdfs`。
3. 在网页终端执行：

```bash
sudo -i
cd /root/zero-waste-portal
docker compose -f deploy/docker-compose.yml up -d --build
docker compose -f deploy/docker-compose.yml exec backend node backend/dist/modules/docs/docs.corpus.sync.cli.js
curl -s http://127.0.0.1:4000/health
```

最后一行仍是 `{"ok":true}`，再用域名点一遍第 7 节的前四项。

### 备份

轻量应用服务器控制台 → 这台实例 → 快照。

- 打开自动快照，每周一次，保留最近 7 份。
- 每次更新程序、更换钥匙之前，手动做一份快照。做完再动手。
- 快照是整台机器的照片。网站打不开且查不出原因时，在快照页面回滚到上一份。回滚会回到拍照的那一刻，拍照之后新注册的账号和新上传的资料会回到拍照前的状态。所以更新之前拍，平时也靠每周那份。

另外三样是网站真正的内容，快照之外不要手动删：

- `/root/zero-waste-portal/backend/data`：账号、书架、对话、上传的文件
- `/root/shelf-corpus`：可检索的正文
- `/root/pdfs`：原文

### 续费

| 项目 | 在哪里看到期日 | 不续会怎样 |
| --- | --- | --- |
| 轻量应用服务器 | 实例列表 | 到期后网站关闭。尽快续费，数据还在；拖太久机器可能被释放 |
| 域名 | 域名控制台 | 过期后网址失效，过了赎回期会被别人注册 |
| 免费 SSL 证书 | SSL 证书页面 | 浏览器出现安全警告 |
| 阿里云百炼 | 阿里云费用中心 | 余额用完后，书架还在，提问不再生成回答 |
| SoMark | 该服务自己的账户 | 只影响新资料转换，已上架的内容不受影响 |

把服务器、域名、证书三个日期写进基金会共用的日历，提前 30 天、证书提前 14 天。

阿里云百炼控制台里设一个每月消费上限。提问按次数计费，上限能避免某一天用量异常时费用一直涨。

### 磁盘快满时

网页终端：

```bash
sudo -i
df -h /
docker system prune -f
```

第二行只清掉已经不用的安装残留，不清资料。清完再看 `df -h`。使用率仍超过 85%，到轻量控制台把系统盘扩容，或把不再公开的 PDF 从 `/root/pdfs` 挪走之前先确认书架已下架。不要删 `/root/shelf-corpus` 和 `backend/data`。

## 10. 打不开时按这个顺序查

一次只查一项，找到第一项异常就停。

1. 轻量控制台里这台机器是「运行中」，还没到期。
2. 域名解析的 A 记录仍是这台机器的公网 IP，官网的 `@` 和 `www` 没有被改掉。
3. 防火墙有 80 和 443，没有误删。8080 和 4000 不必对公众开放。
4. 用域名打开时如果是「未备案」页面，回第 4 节看备案是否通过、域名是否就是备案里的那一个。
5. 浏览器提示证书危险：证书过期或域名和证书不一致。按 6.2 重新签发并覆盖。
6. 网页终端里：

```bash
sudo -i
curl -s http://127.0.0.1:4000/health
docker compose -f /root/zero-waste-portal/deploy/docker-compose.yml ps
systemctl status nginx --no-pager
```

健康检查不是 `{"ok":true}` 时，看最近日志：

```bash
docker compose -f /root/zero-waste-portal/deploy/docker-compose.yml logs --tail 80 backend
```

7. 页面能开，只有提问失败：先看管理 → 系统设置里百炼钥匙是否已配置，再看阿里云账户余额和消费上限。书架和下载不依赖百炼。
8. 以上都正常仍无法恢复：用最近一份快照回滚，并把日志最后 80 行发给维护网站的人。

## 费用分别付给谁

| 付给 | 买的是什么 | 怎么计价 |
| --- | --- | --- |
| 腾讯云 | 域名 | 按年。`.cn` 通常是每年几十元，以付款页为准 |

## 不要做的事

- 不要把 `.env`、证书 `.key`、服务器密码发到微信群或写进文档。
- 不要在防火墙放行 4000。
- 不要用新服务器替换官网的 `@` 和 `www` 解析。知识库只用 `kb` 这一条，或只用新买的域名。
- 不要在更新程序时覆盖 `backend/.env`、`backend/data`、`/root/shelf-corpus`、`/root/pdfs`。
- 不要把服务器地域改到中国香港或境外。那些地域不能用来办这次备案，已经备案的网站指过去也会被拦。
- 不要在两个人同时更新程序。一个人做完快照、更新、打开网页确认，再交给下一个人。
