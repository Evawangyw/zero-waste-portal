# T00 工程脚手架（任务卡）

> 来源：《P3P4-开发总规划与任务拆解.md》v1.1 §6 阶段一 ｜ 派发：2026-10-04 晚

## 目标

初始化 monorepo 骨架，**空壳可跑**：前端占位页 + 后端 health 接口；不做任何业务功能。

## 产出要求

```
zero-waste-portal/
├─ frontend/   # Vite + Vue3 + TS + Element Plus，占位页显示"零废弃知识库"
├─ backend/    # Express + TS(strict) + Prisma + SQLite；GET /health → {"ok":true}
├─ deploy/     # docker-compose.yml（前端+后端两服务即可，WeKnora 不含）、.env.example
├─ docs/       # 本卡、后续验收记录
└─ AGENTS.md   # 已存在
```

## 质量关（全卡通用）

- backend `tsconfig.json`：`strict: true`
- ESLint + Prettier 配置完成，`pnpm lint` 零报错零警告
- `pnpm i` 之后两条命令能起：前端 `pnpm dev`（5173）、后端 `pnpm dev`（4000）
- **验收命令两条都要实测通过**：
  - `curl http://localhost:4000/health` → `{"ok":true}`
  - 浏览器/curl `http://localhost:5173` 看到占位页文字
- Prisma 只建 schema 骨架（User/QuestionLog/DownloadLog/Submission 四表字段照规划 §5），`prisma generate` 通过即可，不要求 migrate 落库（没有 .env 之前）

## 边界（防止积木互踩）

- 不写任何业务路由（docs/auth/embed 全不做）
- 不建 GitHub 远程（主控统一管）
- frontend/backend 谁依赖谁都不允许——本卡就是两个独立空壳

## 回报格式（给主控）

1. 可行性回报（读完卡先回）：目标复述 + 打法 + 预计坑
2. 产出：`ls` 落盘证据 + 两条验收命令的实际回显
3. 遇到的坑与解决（若有）
