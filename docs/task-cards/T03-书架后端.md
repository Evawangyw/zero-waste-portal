# T03 书架页后端（任务卡）

> 来源：规划 v1.1 §6 阶段二 ｜ 依赖：T01 ✅、T02 ✅ ｜ 派发：2026-10-05

## 目标

`/api/docs` 升级成书架数据源：筛选（类型/机构/年份/主题多选）+ 排序（年份正/倒序）+ 分页 + 文件名搜索——全部查自建 `KnowledgeIndex` 索引（不实时打 WeKnora）。

## 需求口径（PRD R03/R07）

- 检索仅文件名（含清洗后的可读标题匹配）；空结果时返回 `zeroResult:true` 字段（前端好挂"试试问 AI"引导）
- 主题多选之间"或"，跨维度"与"；缺失值归"未标注"分组（年份/机构为空也返回，不打死过滤）
- 排序默认年份倒序，年份缺失的排最后；分页 20/页，返回 total
- 文件名清洗规则（PRD §9.3）：去"关于印发…的通知/函"外壳、去文号"（X发〔2024〕X号）"，清洗结果存进索引的 readableTitle 字段参与匹配，原文件名也保留匹配

## 产出要求

- `KnowledgeIndex` 增加可检索字段：readableTitle（清洗后）、year、org、docType、topics（JSON）——从 custom_metadata 解析（键：年份/知识类型/知识领域/知识发布机构）
- `syncIndex()` 同步时填充上述解析字段
- `GET /api/docs?type=&org=&year=&tag=&q=&page=&sort=`：查 SQLite（不调 WeKnora）；支持 `q=` 对 fileName+readableTitle 做 LIKE 匹配
- `GET /api/docs/facets`：返回各筛选维度的枚举+计数（类型/主题/年份列表），供前端筛选项渲染
- 顺手清理：T02 的测试用户保留不动；**把 dev server 里旧的测试路由行为保持不变**

## 验收标准（主控逐条实测）

1. `/api/docs` 默认返回年份倒序、分页 20、带 total 和 zeroResult 字段
2. `/api/docs?type=研究报告`（或库里存在的任一类型值）筛选生效、计数正确
3. `/api/docs?q=<某真实文件名片段>` 命中对应文件；`q=<不存在的词>` 返回 zeroResult:true
4. `/api/docs/facets` 返回各维度枚举+计数
5. 清洗规则有单测（或至少一个自测脚本）：公文壳/文号被剥掉
6. lint/tsc 双零；回报附 ls + curl 回显

## 边界

- 不做前端（T05）；不做详情/预览/下载（T04）；同步仍是手动触发（定时任务 P1）
- 测试库的 42 条数据类型混杂（xlsx/ppt/pdf 都有），以实际存在的元数据值为准写自测，别硬编码"研究报告"这种库里可能没有的值
