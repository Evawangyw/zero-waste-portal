## 1. 数据表 `EventLog`（表名 `event_logs`）

| 列 | 类型 | 说明 |
| --- | --- | --- |
| `id` | String(cuid) | 主键 |
| `event` | String | 事件名，取值见 §2 白名单 |
| `userId` | String? | 用户 ID，**空 = 匿名访客**（任务卡口径）。不建外键：统计不能因删用户而丢 |
| `sessionId` | String(默认 '') | 会话标识（前端生成，存 sessionStorage，换标签页即新会话） |
| `payload` | String(默认 '{}') | 载荷 JSON 串（各事件自定义，≤4000 字符） |
| `path` | String(默认 '') | 页面来源（路由 fullPath，含 query） |
| `createdAt` | DateTime(默认 now) | 事件时间 |
| `term` | String(默认 '') | **派生列**：search 事件的检索词（小写化后原样存），供 Top10/零结果词走索引 |
| `noAnswer` | Boolean? | **派生列**：ai_ask 的无答案判定结果；`null` = **未判定**（前端没上报回答证据） |
| `zeroResult` | Boolean(默认 false) | **派生列**：search 事件的结果是否为零（值来自本服务 `/api/docs` 的 `zeroResult`） |

索引：`event` / `createdAt` / `sessionId` / (`event`,`term`) / (`event`,`noAnswer`)。
三个派生列只服务统计查询（让 summary 走索引而不是 SQLite JSON 函数），**不产生新语义**，真值都在 `payload` 里。

> 说明：`userId` 不建外键是刻意偏离 schema.prisma 里 QuestionLog 的做法 —— 统计表要能承受匿名访客与
> 已注销账号；登出/删号只影响 auth 模块，不影响看板。

## 2. 事件白名单（7 类，任务卡原文）

`page_view` `search` `preview` `download` `ai_ask` `register` `feedback_submit`

不在白名单的单条事件 → 400（整批拒绝），避免脏事件名混进统计。

## 3. `POST /api/track`（统一入口，匿名可传）

请求体三选一（都收）：

```jsonc
// ① 单条
{ "event": "page_view", "sessionId": "s-1", "userId": "u-1", "path": "/shelf?q=垃圾分类", "payload": { "referrer": "" } }
// ② 裸数组（批量）
[ { "event": "page_view", ... }, { "event": "search", ... } ]
// ③ 包装数组
{ "events": [ { ... }, { ... } ] }
```

字段规则：

| 字段 | 必填 | 约束 |
| --- | --- | --- |
| `event` | 是 | §2 白名单之一 |
| `sessionId` | 否 | 字符串，≤64 字符；缺省 `''`（= 无会话） |
| `userId` | 否 | 字符串，≤64 字符；缺省/空串 → `null`（匿名） |
| `path` | 否 | 字符串，≤512 字符；缺省 `''` |
| `payload` | 否 | 必须是**普通对象**（不能是数组/标量/null）；序列化后 ≤4000 字符，缺省 `{}` |

响应：

```jsonc
201 { "success": true, "accepted": 3, "rejected": [ { "index": 1, "code": "UNKNOWN_EVENT", "message": "..." } ] }
400 { "success": false, "error": { "code": "VALIDATION_FAILED", "message": "...", "issues": [ { "index": 0, "code": "...", "message": "..." } ] } }
```

- 单次请求**最多 100 条**（超过 400）。
- **允许部分成功**：合法条数写入，非法条数进 `rejected`；`accepted` 必须等于本次实际落库行数（验收①）。
- 只有信封本身不可用（不是对象/数组、空数组、全部条目非法）才回 400。
- 本卡**不做服务端鉴权**：埋点是公众侧匿名行为。`userId` 来自前端登录态，P2 接 RBAC 时再收紧。
- 前端 fire-and-forget：任何非 2xx 都不影响用户操作（前端 `api/track.ts` 吞异常）。
- 请求体畸形（非法 JSON、`"hello"` 这种原始值、超过 1MB）由 body-parser 在进路由前拦下，
  故 `app.ts` 末尾挂了 `trackJsonErrorHandler` **只对 `/api/track`** 转成同一套 JSON 错误体；
  其余路径原样 `next(err)` 交还 Express 默认处理 —— 既有路由的报错行为一个字节都不变。

## 4. `GET /api/admin/stats/summary`（暂用简单口令，正式 RBAC 是 P2）

守卫（两条任一通过）：

1. **静态口令**：请求头 `X-Admin-Token: <值>` 与环境变量 `ADMIN_STATS_TOKEN` 常量时间比较相等。
   - 未配置 `ADMIN_STATS_TOKEN` 时该路径**自动失效**（不是 503），回落到第 2 条；源码里**零口令字面量**。
   - 基金会实例交付时往 `backend/.env` 加一行即可启用（口令不进代码、不进 git）。
2. **管理员 JWT**：`Authorization: Bearer <token>` 先过 auth 模块导出的 `requireAuth`（401 由 auth 给），
   再查 `users.isAdmin === true`；否则 403。
   - 提管理员用运维 CLI（只写 `isAdmin` 一列、不建号）：
     `npm run admin:promote --workspace backend -- <11位手机号> [--revoke]`；无参运行只列当前管理员。

两条都不可用时（本机当前状态：`.env` 未配 `ADMIN_STATS_TOKEN`，测试账号已提为 `isAdmin`），
端点不会 503，只是静态口令那条路走不通 —— 不设"默认口令"后门。

响应 `200`：

```jsonc
{
  "success": true,
  "generatedAt": "2026-10-05T00:00:00.000Z",
  "totals": { "events": 42, "pv": 10, "uv": 3, "registeredUsers": 2 },
  "events": { "page_view": 10, "search": 4, "preview": 1, "download": 2, "ai_ask": 3, "register": 1, "feedback_submit": 0 },
  "topSearchTerms": [ { "term": "垃圾分类", "count": 3 } ],
  "zeroResultSearchTerms": [ { "term": "量子计算", "count": 1 } ],
  "topDownloads": [ { "docId": "uuid", "fileName": "2021-市生态环境局-实施方案.pdf", "count": 2 } ],
  "downloads": { "logRows": 2, "events": 2 },
  "asks": { "total": 3, "judged": 2, "noAnswer": 1, "unjudged": 1, "noAnswerRate": 0.5 }
}
```

口径（**必须按此解释数字**）：

- `pv` = `event='page_view'` 的事件条数（不含其他事件）。
- `uv` = 全事件按「访客身份」去重的个数：`COALESCE(userId, sessionId)`，两者都空的事件不计入。
- `registeredUsers` = `users` 表总行数（注册埋点只是交叉验证，不作为口径）。
- `topSearchTerms` / `zeroResultSearchTerms` = search 事件按 `term` 分组，取前 10；零结果词只取 `zeroResult=true`。
  同词不同大小写/首尾空格视为同一个词（入库前归一）。
- `topDownloads` = **读 `download_logs`（T04 的 DownloadLog）**，按 `docId` 分组取前 10 —— 见 §6 双写决策。
- `downloads.logRows` = DownloadLog 行数；`downloads.events` = EventLog 里 `download` 事件数（两者不等时说明有绕过前端直连接口的调用）。
- `asks`：`total` = ai_ask 事件总数；`judged` = `noAnswer IS NOT NULL` 的条数；`noAnswer` = `noAnswer=true`；
  `unjudged` = `noAnswer IS NULL`；**`noAnswerRate` = noAnswer / judged**（judged=0 时给 0）。
  未上报回答证据的提问算「未判定」，不进分母 —— 不能把"没测到"当成"有答案"（否则无答案率被系统性低估）。
  当全部提问都带回答证据时 judged==total，此时与任务卡「无答案提问/总提问」完全等价。

## 5. 无答案判定规则（验收④）

输入：`ai_ask` 事件的 `payload`：

| 字段 | 含义 |
| --- | --- |
| `answer?: string` | 挂件回答文本（前端截断到 ≤2000 字符） |
| `sources?: string[]` | 来源/引用（文件名或片段标题） |
| `hasSource?: boolean` | 显式声明有无来源 |

`judgeNoAnswer(payload)` 纯函数，**三态** `true | false | null`：

1. 命中**无答案短语** → `true`。
   判定前先归一化：NFKC（全角→半角）+ `toLowerCase()` + 去掉所有空白字符。
   短语表（正则，中文/英文大小写与全半角均归一后再匹配）：

   ```
   无法回答 | 无法提供(信息|依据)? | 抱歉[,，。]?
   (知识库|知识库中|知识库里|知识库内|库中|库内)(没有|无|未收录|找不到)
   (没有|未)(找到|检索到|搜索到)
   未找到(相关)?(资料|内容|文献|依据|文件)?
   不(包含|涵盖)(相关)?(资料|内容|信息|文献)?
   暂无(相关)?(资料|内容|数据)
   ```

2. 否则，若来源**明确为空**（`hasSource === false` 或 `sources.length === 0`）→ `true`。
3. 否则，若来源**明确非空**（`hasSource === true` 或 `sources.length > 0`）→ `false`。
4. 否则（有 `answer` 但没给来源信息，或什么都没给）→ `null`（未判定）。

**顺序固定**：先短语、再来源。短语优先的理由：引擎偶尔会一边说"无法回答"一边带上兜底来源，
按任务卡口径「回答里说无法回答就算无答案」，人的明确表述优先于机器的兜底引用。

自测（`npm run test:track`）必须覆盖：短语命中／来源为空／来源非空／仅 answer 无来源→未判定／
全空→未判定／**反例**「本回答不包含个人信息，仅引用公开政策原文」+ 非空来源 → 有答案
（证明短语表把 `不包含` 收窄到「不包含(相关)资料/内容/信息/文献」，不会误伤正常回答）。

已知边界（**必须如实向主控说明**）：官方挂件 v0.8.2 没有回答回调/webhook，
浏览器里用户**直接在挂件面板里打字**的提问，我们拿不到 `answer` 与 `sources` →
该类事件记为 `ai_ask` + `noAnswer=null`（未判定）。
因此 `asks.total` ≥ 真实全量提问数；无答案率只对「站内发起的提问（可拿到回答证据）」负责。
要 100% 覆盖需要 P2 自建问答 UI（我们自己的 `/api/ask` 有完整 SSE，可直接接判定）。

## 6. download：**双写**（拍板 + 理由）

任务卡给了两个选项，本卡选**双写**，且双写**分离在两个写入方**：

| 表 | 写入方 | 覆盖 | 用途 |
| --- | --- | --- | --- |
| `download_logs` | T04 后端 `GET /api/docs/:id/download`（**一行不改**） | 所有已授权下载尝试（含 curl 直连） | 看板下载 Top10 的**权威口径** |
| `event_logs` | 前端 `api/track.ts`（下载成功后埋点） | 浏览器内发起的下载 | 行为流（与 page_view/search 同表同源，供漏斗分析） |

理由：
1. **铁律⑦ + AGENTS 边界**：T04 的 DownloadLog 是已验收模块的既有行为，把统计塞进 `docs.file.service.writeDownloadLog`
   等于改别人模块的副作用，跨卡改动要先报主控；前端埋点零侵入。
2. **可信度分层**：DownloadLog 服务端写、可信（含绕过前端的直连）；EventLog 是客户端行为流，可能被伪造/丢失。
   看板下载排行必须用可信口径，故 `topDownloads` 读 DownloadLog，EventLog 只做对齐（`downloads.events` 与
   `downloads.logRows` 不等时本身就是一条"有接口被直连"的信息）。
3. **不合并成一张表**：download 需要 `userId` 强外键 + `docTitle/fileName` 语义列做历史留痕，
   事件表是弱语义 JSON 流；硬合并会既破坏 T04 契约又让下载统计依赖客户端上报。

## 7. 前端埋点接入点（只增不改，不动既有返回结构）

| 事件 | 接入点 | payload |
| --- | --- | --- |
| `page_view` | `router/index.ts` 的既有 `afterEach`（追加几行，不改标题逻辑） | `path` 走 `path` 列；载荷 `route`/`from`/`referrer` |
| `search` | `ShelfView.onSearch()`（按钮/回车/清空）→ 等 `loadList()` 回来再补 `zeroResult` | `term`、`filters`、`total`、`zeroResult` |
| `ai_ask` | `composables/useWidget.ts` 的 `askWidget()`（首页示例问题/自定义问题、书架零结果"试试问 AI" 的**唯一收口**） | `question`、`source`（页面来源）、`judged:false` |
| `register` | `AuthView.onRegister()` 成功分支 | `org`、`occupation`、`topics`（不记密码/手机号） |
| `download` | `DocDetailView.doDownload()` 成功后 | `docId`、`fileName`、`title` |
| `preview` | `DocDetailView.loadPreview()` 成功开流后 | `docId`、`fileType`、`sizeBytes`、`title` |
| `feedback_submit` | **暂不接**（无反馈页）；接口先收，P2 页面接上即用 | — |

### PV 计数规则

`page_view` 只在**页面（route path）变化**时计一次：首次进入必计（vue-router `START_LOCATION` 的
`matched` 为空），只改 query（书架筛选/搜索/分页/排序）**不重复计 PV**，但 `fullPath` 仍原样写进
`path` 列与 payload —— 这样看板既能算页面访问量，也能还原"在哪一页搜了什么"。

### 埋点绝不弄坏页面

前端所有埋点出口统一走 `useTracking.ts` 的 `emit()`，整段 try/catch：组装输入是**同步**代码，
一旦抛错会顺着 `afterEach` / 事件处理器冒泡成白屏。（真踩过：把 `crypto.randomUUID` 摘出来
当普通函数调用，在 Chrome 里抛 `TypeError: Illegal invocation`，直接把路由启动打断。）

统一出口：`frontend/src/api/track.ts`（`trackEvent` / `trackBatch`，吞异常、不阻塞 UI）+ `composables/useTracking.ts`（语义化 helper + `sessionId`）。

会话标识：`sessionStorage['zwp.track.sid']`，首次访问 `crypto.randomUUID()` 生成；换标签页=新会话，刷新不变。
未登录时 `userId` 为空（匿名），登录后带 userId（后端不强校验，只作统计维度）。
**前端不上报 JWT**：/api/track 不做服务端鉴权，没必要把登录凭证发到公开的统计接口上。
