# T07 行为统计落库（任务卡）✅ 验收通过 2026-10-05（P0 收官）

> 来源：规划 v1.1 §6 阶段三 ｜ 依赖：T02✅、T05T06✅ ｜ 派发：2026-10-05（P0 最后一卡）

## 目标

把"谁在用、在找什么"记下来：统一埋点事件表 + 前端埋点接入 + 管理员统计查询接口。

## 需求口径（PRD 第八节，R04 基础版）

埋点 7 类事件（page_view/search/preview/download/ai_ask/register/feedback_submit）→ 统一一张 `EventLog` 表（事件名、用户ID可空=匿名、会话标识、载荷JSON、时间、页面来源）。

- 前端已做的动作顺手接埋点：下载（T04 已写 DownloadLog，保留并**同步写一条** download 事件或改为统一事件表——你拍板选一种并说明理由）、search（书架搜索提交时）、ai_ask（挂件提问时）、page_view（路由切换时）、register（注册成功时）
- 统一入口：`POST /api/track`（批量数组也收），匿名访客可传（用户ID空）
- 管理端查询（暂用简单管理员口令保护即可，正式 RBAC 是 P2）：`GET /api/admin/stats/summary` 返回：PV、UV、检索Top10词、零结果词、下载Top10、提问数/无答案率、注册用户数

## 验收标准（主控逐条实测）

1. `POST /api/track` 单条+批量各一次 → EventLog 落库行数对得上
2. 走一遍真实用户路径（curl 层面模拟）：注册→page_view→search→ai_ask → summary 里各计数正确变化
3. `GET /api/admin/stats/summary` 返回上述字段且数字正确（无答案率：无答案提问/总提问）
4. 无答案判定：挂件回答里"无法回答/库内没有"或来源为空算无答案（规则写清并自测）
5. lint/tsc 双零；回报附 ls + curl 回显
