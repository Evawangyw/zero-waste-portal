# T04 文件详情/预览/下载（任务卡）

> 来源：规划 v1.1 §6 阶段二 ｜ 依赖：T01✅、T02✅、T03✅ ｜ 派发：2026-10-05

## 目标

`/api/docs/:id` 详情 + `/api/docs/:id/preview` 在线预览 + `/api/docs/:id/download` 下载（登录闸门），全部经 weknora 客户端转发。

## 需求口径（PRD R08/R09）

- 预览：桌面走浏览器原生（后端透传 PDF 流即可）；文件 >20MB 时返回 `tooLarge:true` 引导下载（阈值可配常量）
- 下载：**必须登录**（未登录 401）；下载时写 `DownloadLog` 表（userId+knowledgeId+时间）；文件名按"年份-机构-标题.ext"重命名（缺年份/机构时跳过该段，处理非法字符），Content-Disposition 带文件名
- 详情：元数据全量（含 custom_metadata 解析后的 年份/机构/类型/领域）+ 摘要（WeKnora description）

## 产出要求

- 三个路由挂到 docs 模块（`backend/src/modules/docs/`，沿用 shelf 的索引优先原则：详情先查索引再回源 WeKnora）
- DownloadLog 表 migrate 落库
- 预览/下载走 `weknoraClient` 的流式透传（别把 5MB PDF 整个读进内存）

## 验收标准（主控逐条实测）

1. `/api/docs/:id` 用 42 条里任一真实 id 返回详情（含解析后的元数据字段）
2. `/api/docs/:id/preview` 返回 PDF 流（Content-Type 正确；x lsx 等 PDF 之外的类型给 `unsupported:true` 提示）
3. 未登录 `/api/docs/:id/download` 返回 401；带 T02 验收员的 token 返回 200 且 Content-Disposition 有重命名文件名；下载两次后 `DownloadLog` 有两条记录
4. 大文件阈值逻辑：`tooLarge` 字段存在（用 size 字段判断，不必真找 20MB 文件，说明实现即可+自测脚本证明分支可达）
5. lint/tsc 双零；回报附 ls + curl 回显

## 边界

- 不做前端（T05）；不动 auth/shelf 已验收代码；下载排队记录用户id要解 JWT（用 T02 的中间件）
