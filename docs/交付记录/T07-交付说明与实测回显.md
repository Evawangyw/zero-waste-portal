## 2. download：**双写**（拍板 + 理由）

| 表 | 写入方 | 覆盖 | 用途 |
| --- | --- | --- | --- |
| `download_logs` | T04 后端 `GET /api/docs/:id/download`（**一行未改**） | 所有已授权下载尝试（含 curl 直连） | 看板下载 Top10 **权威口径** |
| `event_logs` | 前端 `api/track.ts`（下载成功后埋点） | 浏览器内发起的下载 | 行为流（与 page_view/search 同表做漏斗） |

理由三条：① 铁律⑦/AGENTS 边界——把统计塞进 `docs.file.service.writeDownloadLog` 等于改别人已验收模块的
副作用，跨卡改动要先报主控；前端埋点零侵入。② 可信度分层——DownloadLog 服务端写、可信，EventLog 是
客户端行为流可丢失/可伪造，看板排行必须用可信口径。③ 不合并成一张表——download 需要 `userId` 强外键 +
`docTitle/fileName` 语义列做历史留痕，事件表是弱语义 JSON 流，硬合并会既破坏 T04 契约又让下载统计
依赖客户端上报。

实测两写都在（见 §3 步骤 8/9 与 §3 末尾 summary 的 `downloads`）。

### 验收④ 无答案判定：规则 + 自测 + 落库可查

规则（三态，判定顺序固定：短语 → 来源数组 → hasSource）：

1. 归一化（NFKC 全角转半角 + 小写 + 去所有空白）后命中无答案短语 → **无答案**
   `无法回答` / `无法提供(信息|依据)` / `抱歉(无法|不能|暂不|没有)` /
   `(知识库中|里|内|库中|库内)(没有|无|未收录|找不到)` / `(没有|未)(找到|检索到|搜索到)` /
   `未找到(相关)?(资料|内容|文献|依据|文件)` / `不(包含|涵盖)(相关)?(资料|内容|信息|文献)` /
   `无(相关)?(资料|内容|信息|文献|依据)` / `暂无(相关)?(资料|内容|数据)`
2. 否则来源明确为空（`hasSource=false` 或 `sources=[]`）→ **无答案**（任务卡口径）
3. 否则来源明确非空 → **有答案**
4. 都没有 → **未判定**（不进无答案率分母）

短语优先的理由：引擎偶尔一边说"无法回答"一边带兜底来源，按任务卡口径人的表述优先。

```console
$ npm run test:track     # 34 项断言，全 PASS
[验收④] 无答案判定规则（judgeNoAnswer 三态）
  PASS  短语命中-知识库里没有            说"知识库里没有"即使带兜底来源也算无答案（短语优先）
  PASS  短语命中-无法回答（全角+空白归一）  归一化输入："抱歉,我无法回答这个问题"
  PASS  短语命中-库内没有                 "库内没有"命中
  PASS  来源为空                      有文字但 sources=[] -> 无答案
  PASS  来源为空（hasSource=false）      hasSource=false -> 无答案
  PASS  有答案（来源非空且未命中短语）
  PASS  反例-免责话术不误判               "本回答不包含个人信息..." 仍判有答案
  PASS  未判定-只有 answer 没有来源信息     -> null
  PASS  未判定-只有问题 / 空 payload / payload 不是对象 -> null
  PASS  短语匹配空串不命中
```

线上逐行验证（4 条受控提问落库后的 `noAnswer` 列）：

```
true   | 请问本库的收录范围？   | answer= 抱歉，我无法回答这个问题。 | sources= []
true   | 塑料污染治理有哪些指标？ | answer= 塑料污染治理涉及源头减量…    | sources= []
false  | 垃圾分类考核要求？     | answer= 依据实施方案，考核指标包含…  | sources= ["2019-上海市…pdf"]
null   | 零废弃政策有哪些？     | answer= (无)                  | sources= null
```

summary 侧对账：`asks{total:5, judged:4, noAnswer:2, unjudged:1}`，`noAnswerRate = 2/4 = 0.5` ✅

> **已知边界（如实说明）**：官方挂件 v0.8.2 无回答回调/webhook，浏览器里**直接在挂件面板打字**的提问
> 拿不到 `answer/sources`，记为"未判定"（`unjudged`）。所以 `asks.total` ≥ 真实全量提问数，
> 无答案率只对"能拿到回答证据的提问"负责。要 100% 覆盖需 P2 自建问答 UI（我们的 `/api/ask` 有完整 SSE）。

**真机抓到并修掉的一个 bug**（第一轮真机验证 console 报 `[Vue Router warn] Unexpected error when
starting the router: TypeError: Illegal invocation`）：`useTracking` 里把 `crypto.randomUUID` 摘出来
当普通函数调用（`const f = crypto.randomUUID; f()`），丢了 `this`，Chrome 抛 Illegal invocation，
异常顺着 `router.afterEach` 冒泡 —— **整个首页起不来**。改成带 `crypto` 对象调用，并把所有埋点出口
统一包进 `emit()` 的 try/catch（组装是同步代码，抛错就会打断页面）。修复后重跑真机：console 无任何
报错，page_view / ai_ask / search 三类事件全部落库。
