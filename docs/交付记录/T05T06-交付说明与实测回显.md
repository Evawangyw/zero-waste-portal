## 2. 主控已实测事实之外，我本轮实测补上的 3 条

卡面给的是「`http://localhost:8080` + exchange 接口」，但**8080 上没有静态挂件**。实测结论：

| # | 事实 | 回显 |
| --- | --- | --- |
| A | **WeKnora 前端/nginx 在 80 端口**，8080 只是 Go API | `curl -o /dev/null -w %{http_code} http://localhost/weknora-widget.js` → `200`；`http://localhost:8080/weknora-widget.js` → `401 {"error":"Unauthorized: missing authentication"}` |
| B | `/embed/{channel}` 的 CSP 已含我们的宿主 | `HTTP/1.1 200` + `Content-Security-Policy: frame-ancestors 'self' http://localhost:3000 http://localhost:5173` |
| C | exchange 必须走请求头 Origin（与卡一致，且已复测） | 带 `Origin: http://localhost:5173` → `200 {"success":true,"data":{"session_token":"ems_...","expires_in":1800}}`；不带/带 `http://evil.example.com` → `403 {"error":"origin not allowed"}` |

## 3. 挂件接法（严格照官方文档 `13-embed-channel.md` 方式二「安全模式」）

```
<script src="http://localhost/weknora-widget.js"
        data-channel="67fd8c57-..."           <- 渠道 UUID（非密钥，公开可见）
        data-token-endpoint="http://localhost:4000/api/embed/token"
        data-base-url="http://localhost"
        data-position="bottom-right"
        data-title="零废弃知识库助手"></script>
```

- **`data-token` 一律不给**：publish token（`em_`）只存在 `backend/.env` 与后端进程内存，浏览器永远拿不到。自测里有专门一条断言「config 响应体内无 `em_` 串」。
- 静默续期用官方 loader 自带的 `scheduleRefresh`（约 80% TTL 换一次），前端不自己写续期逻辑，避免与官方重复实现打架。
- 零结果页 / 首页示例问题都走官方 `WeKnora.openWithQuery(q)`，**不自写问答 UI**。

### 一处必须报备的契约增补：为什么同时开了 `GET`

官方 loader 取 token 只发 `GET`（`weknora-widget.js` 第 101 行 `fetch(tokenEndpoint, { method: 'GET', credentials: 'include' })`）。任务卡写的是 `POST`。解法是 **GET 与 POST 指向同一个处理器**（`embed.router.ts` 的 `tokenHandler`），校验与交换逻辑物理上只有一份，不存在两条路径漂移。卡里的 POST 契约原样保留且是主契约。

### 一处必须报备的安全判定增补：同源豁免

浏览器**同源 GET 不带 Origin 头**（Fetch 规范）。若生产把 `/api` 反代到与站点同源，挂件会永远换不到 token。故加了一条极窄豁免（`embed.service.ts: assertOriginAllowed` / `isSameOriginBrowserFetch` / `reconstructRequestOrigin`）：

> 仅当 **Origin 缺失** 且 `Sec-Fetch-Site: same-origin`（浏览器强制附加，页面 JS 无法伪造）且 **由 Host 还原出的本站 Origin 也在白名单里**，才放行。

- Origin **存在**时一律严格比对白名单，豁免不生效（已单测）。
- curl 等非浏览器客户端不带 `Sec-Fetch-*`，仍按「缺 Origin」拒绝 → **验收标准②原样成立**。

**若主控认为这条越界，请指示，我删掉它，改为部署时保证前后端分源。**

### ③ 挂件窗内真实提问 —— **被 WeKnora 容器侧配置挡住，非本卡代码问题**

链路逐段已通：

```
$ curl -s http://localhost:4000/api/embed/token -H "Origin: http://localhost:5173"   -> 200（拿到 ems_ 短效 token）
$ curl -s http://localhost:8080/api/v1/embed/$CH/config   -H "Authorization: Embed $TOK" -H "Sec-Fetch-Site: same-origin"
{"data":{"channel_id":"67fd8c57-...","agent_id":"builtin-quick-answer",
 "allowed_origins":["http://localhost:3000","http://localhost:5173"],
 "widget_position":"bottom-right","show_suggested_questions":true,...},"success":true}
HTTP 200                                                              <- 挂件 iframe 拉配置成功

$ curl -s http://localhost:8080/api/v1/embed/$CH/suggested-questions -H "Authorization: Embed $TOK" ...
{"data":{"questions":[{"question":"顺丰莲花助学项目...","source":"document",
 "knowledge_base_id":"ab5f8c28-1231-4a9e-93b0-a707af652d40",...}]},"success":true}
                                                                     <- 推荐问题成功

$ curl -s -X POST http://localhost:8080/api/v1/embed/$CH/sessions -H "Authorization: Embed $TOK" ...
{"error":"embed session signing key is not configured"}
HTTP 503                                                              <- 建匿名会话失败 = 挂件无法发第一句话
```

**根因**（WeKnora 源码 `internal/handler/embed_channel.go:398`）：

```go
if len(secutils.SystemHMACKey()) == 0 {
    c.JSON(http.StatusServiceUnavailable, gin.H{
        "error": "embed session signing key is not configured: set SYSTEM_SIGNING_KEY on the server",
    })
```

`E:/projects/WeKnora/.env:563` 是 `SYSTEM_SIGNING_KEY=`（空），`docker-compose.yml:305` 原样透传给容器 → 匿名会话签名密钥为空。

**修法（需主控执行，我禁 Docker）**：在 `E:/projects/WeKnora/.env` 给 `SYSTEM_SIGNING_KEY` 填一个随机长串（重启容器生效），再打开首页点示例问题即可。
