## 8. 遇到的坑与解决

| # | 坑 | 现象 | 解决 |
| --- | --- | --- | --- |
| 1 | pnpm 不存在 | `which pnpm` 无输出 | 按任务书授权改用 npm workspaces 等价命令；根 `package.json` 的 scripts 与 pnpm 版一一对应 |
| 2 | ESLint 类型感知规则 | `no-unsafe-assignment` 报"需 type information" | 给 `.ts` 文件单开一段 `parserOptions.projectService: true`；`.vue` 走 `vue-eslint-parser` + `vue-tsc`，避免解析器冲突 |
| 3 | `@typescript-eslint/ban-types` 已移除 | ESLint 报 `Could not find "ban-types"` | 换成 v8 现存等价规则 `no-empty-object-type` + `no-wrapper-object-types` + `no-unsafe-function-type` |
| 4 | Prisma datasource 变量名 | 若写 `DATABASE_URL`，而既有 `.env` 里只有 `DB_URL`，会生成失败 | schema 直接 `env("DB_URL")`，**不改动 .env**（任务书红线） |
| 5 | Prisma 关系缺反向字段 | `The relation field \`user\` on model \`Submission\` is missing an opposite relation field` | 在 `User` 上补 `questions` / `downloads` / `submissions` 三个反向关系字段 |
| 6 | Windows 下 Prisma 崩溃噪音 | schema 校验失败后 `Assertion failed: !(handle->flags & UV_HANDLE_CLOSING)` | 是 Prisma CLI 在 Windows 的收尾 bug，非本卡问题；修好 schema 后不再出现 |
| 7 | 后端 build 产物 | `dist/index.js` 直接跑会因 ESM/`.js` 后缀要求 `"type": "module"` | `backend/package.json` 未设 `type: module`，改用 `module: NodeNext` + `tsconfig.build.json` 单独覆盖模块解析，`tsx watch` 与 `node dist/index.js` 两条路径都验证过 |
